# 📱 MobileTopUp — автопополнение мобильных игр через DesslyHub

Плагин для [FunPay Cardinal](https://github.com/sidor0912/FunPayCardinal) **v0.1.17+**

**Автор:** yungspider

Покупатель оплатил лот «Донат в PUBG / Free Fire / Mobile Legends…» — плагин сам собирает
нужные данные игрока (Character ID, Player ID, Server и т.п.) из полей заказа или из чата,
покупает пополнение через API [DesslyHub](https://desslyhub.com/ru) и следит за транзакцией до
статуса `success` / `failed`, сообщая покупателю результат.

## Как это работает

```
новый заказ FunPay
      ↓
привязка лота: «Донат PUBG 60 UC» → ID игры 123 + ID номинала 492 (+ источник 1/2)
      ↓
обязательные поля игры: ищем в полях заказа по псевдонимам → чего не хватает,
спрашиваем в чате и ждём wait_data_minutes (значения подхватываются из сообщений)
      ↓
проверки: баланс DesslyHub, лимит стоимости, минимальная маржа, ЧС
      ↓
каталог: игра → номинал (позиция) и его цена в USD
покупка: mobile_refill {position, fields}  → transaction_id (reference = номер заказа)
      ↓
опрос статуса              → pending → success / failed / cancelled
      ↓
success → покупателю «$game - $position отправлено» · failed → алерт продавцу
```

## Возможности

- 📱 **Полный цикл по API DesslyHub**: каталог игр → позиции (номиналы) и обязательные
  поля → пополнение (`mobile_refill`) → опрос статуса транзакции/заказа до финала.
- 🌐 **Два поколения API**: legacy (заголовок `apikey`, источники variant 1/2) и v2
  (HMAC-подпись `key+secret`, единый эндпоинт `/orders`) — определяется автоматически.
- 🎮 **Встроенный поиск по каталогу игр прямо в меню**: находите игру, смотрите номиналы,
  цены и обязательные поля, копируете готовые строки для привязки.
- 🔗 **Привязка лотов через меню**: `Название лота | ID игры | ID номинала [| источник]`.
- 🔤 **Данные игрока собирает сам**: обязательные поля (Character ID и т.п.) ищутся в полях
  заказа по **настраиваемым псевдонимам**; чего не хватает — спрашивает в чате и ждёт,
  принимая значения в свободном формате (`название поля: значение`).
- 🧪 **DRY-RUN по умолчанию** — весь сценарий проходит, но покупка **не совершается**.
- 🛡 **Защита денег**: порог баланса DesslyHub, лимит стоимости, минимальная маржа
  (цена позиции в USD против цены лота FunPay), **ровно одна покупка на заказ**.
- ⚠️ **Понятные ошибки по-русски**: `-200` игра не найдена, `-201` позиция (номинал)
  не найдена, `-2` недостаточно средств и т.д.
- 🔁 **Сетевые сбои ретраятся**, бизнес-ошибки — нет (деньги не тратятся дважды).
- 💾 Состояние на диске: перезапуск Кардинала не теряет заказы; оборванная покупка
  **не повторяется автоматически** (заказ передается вам).
- 📋 Меню `/mobile`: баланс, каталог игр, псевдонимы полей, привязки, история, лимиты, тексты.

## Установка

```bash
cd /home/fpc/FunPayCardinal
wget https://raw.githubusercontent.com/yungspiderq/FPC-MobileTopUp/main/mobile_topup.py -O plugins/mobile_topup.py
sudo systemctl restart FunPayCardinal@fpc
```

или отправьте файл боту в Telegram → `🔌 Плагины` → `➕ Добавить плагин`.

> ⚠️ Лоты с донатом **не должны** быть в `configs/auto_delivery.cfg` — иначе Кардинал
> выдаст «товар» сам, вместе с донатом.

## Первый запуск (по шагам)

1. `/mobile` → **🔑 API-ключ** (и **🔐 Секрет**, если у вас ключ v2) — выдаёт менеджер
   DesslyHub ([@DesslyHub_Manager](https://t.me/DesslyHub_Manager)).
2. **🧪 Тест подключения** — покажет поколение API, баланс и курс RUB.
3. **🎮 Каталог игр → 🔎 Поиск** — введите название (например `PUBG`), выберите игру,
   посмотрите номиналы (позиции) с ценами и ID, скопируйте строку привязки.
4. **📦 Привязки лотов → ➕ Добавить**:
   ```
   Донат PUBG 60 UC | 123 | 492
   Донат PUBG 60 UC (ист. 2) | 123 | 492 | 2
   ```
   Четвёртое поле — источник (variant) для legacy API (1 или 2); в v2 игнорируется.
5. Если поля заказа у вас называются иначе, чем в каталоге DesslyHub, добавьте
   **🔤 Псевдонимы полей**: `Character ID: uid, id персонажа`.
6. Сделайте **тестовый заказ**, оставив **DRY-RUN включенным**: придет карточка
   «что было бы куплено» — игра, номинал, цена, собранные поля.
7. Проверьте карточку и только затем **выключайте DRY-RUN** и включайте плагин.

| 🔑 API-ключ / 🔐 Секрет (v2) | Ввести ключ и секрет DesslyHub (в меню маскируются) |
| 💳 Баланс | Всего / доступно / резерв / овердрафт мерчанта DesslyHub |
| 🧪 Тест подключения | Поколение API + баланс + курс RUB |
| 🎮 Каталог игр | Поиск игры, номиналы и цены, обязательные поля, строки привязок |
| 🔤 Псевдонимы полей | Список, ➕ добавление, 🗑 удаление псевдонимов |
| 📦 Привязки лотов | Список, ➕ добавление, 🗑 удаление |
| 🧾 История операций | Последние заказы: статус, игра, номинал, цена, текст ошибки |
| 🔄 Проверить транзакции | Немедленно опросить статусы всех активных транзакций |
| 🛡 Лимиты и защита | Лимит покупки, порог баланса, маржа, валюта FunPay, ожидание данных |
| 💬 Тексты сообщений | Текст запроса данных, текст после успеха, текст при ошибке |
| 🌐 API: auto/legacy/v2 | Переключение поколения API |

### Тексты по умолчанию

Запрос данных игрока (к нему автоматически добавляется список недостающих полей):

```
Здравствуйте, $username! Спасибо за покупку 📱
Чтобы отправить пополнение, пришлите данные вашего аккаунта (список ниже).
Их можно прислать одним сообщением в формате:
название поля: значение
```

После успешного пополнения:

```
📱 Пополнение отправлено: $game - $position!
Данные: $fields
Обычно донат приходит в течение 5-30 минут. Если задержалось - напишите, я на связи.
Спасибо за покупку, $username! Будем рады вашему отзыву ⭐
```

Во всех текстах работают переменные Кардинала (`$username`, `$order_desc`, …), `$order`
(номер заказа), `$game` (игра), `$position` (номинал) и `$fields` (собранные данные).
При ошибке покупателю по умолчанию **ничего не отправляется** (`failed_text` пустой).

## Настройки

`storage/plugins/mobile_topup/settings.json` — можно править руками (перечитывается при каждом
обращении) или через меню `/mobile`.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `false` | master-switch: обрабатывать ли заказы |
| `dry_run` | `true` | тестовый режим — покупка не совершается |
| `apikey` / `secret` | `""` | ключ DesslyHub и секрет для API v2 (HMAC) |
| `api_mode` | `auto` | `auto` / `legacy` / `v2` — поколение API |
| `base_url` | `https://desslyhub.com` | адрес API |
| `timeout` / `retries` | `20` / `2` | таймаут запроса и число повторов при сетевом сбое |
| `default_variant` | `1` | источник (variant) по умолчанию для legacy API |
| `field_aliases` | `{}` | псевдонимы: `{ "Character ID": ["uid", "id персонажа"] }` |
| `ask_for_data` | `true` | спрашивать ли недостающие поля в чате |
| `ask_data_text` | см. выше | текст запроса данных |
| `wait_data_minutes` | `60` | сколько ждать данные от покупателя |
| `success_text` | см. выше | сообщение покупателю после успеха |
| `failed_text` | `""` | сообщение покупателю при ошибке (пусто = не отправлять) |
| `poll_interval` | `10` | интервал опроса статусов транзакций, секунд |
| `poll_max_minutes` | `90` | после этого транзакция считается «зависшей» → алерт |
| `min_balance_usd` | `5` | порог баланса DesslyHub (ниже — не покупаем + алерт) |
| `max_order_cost_usd` | `100` | лимит стоимости одного пополнения |
| `min_margin_percent` | `0` | минимальная маржа, `0` = проверка выключена |
| `funpay_currency_code` | `5` | код валюты цены заказа (5 RUB, 1 USD, 3 EUR, 18 UAH, 37 KZT) |
| `notify_low_balance` | `true` | уведомление в Telegram о низком балансе |
| `low_balance_repeat_minutes` | `60` | пауза между повторными алертами, минут |
| `mappings` | `{}` | привязки лотов: `{ "название лота": {"game_id":…, "position_id":…, "variant":1} }` |
| `catalog_cache_minutes` | `720` | время жизни кэша каталога |

Данные: `storage/plugins/mobile_topup/orders.json` (журнал заказов и транзакций),
`storage/plugins/mobile_topup/catalog.json` (кэш каталога).

## Важно знать

- **Деньги.** Покупка совершается только при выключенном `dry_run` и только после всех
  проверок. На один заказ — ровно одна покупка: повторные события FunPay и перезапуск
  Кардинала не приводят ко второму списанию.
- **Перезапуск во время покупки.** Заказ помечается `error` и приходит алерт — автоматически
  повторять нельзя (неизвестно, успел ли запрос дойти). Проверьте операции DesslyHub.
- **Поля игрока.** Точные имена обязательных полей показывает каталог (`🎮 Каталог игр →
  игра → номинал`). Удобнее всего сделать в лоте FunPay поля с теми же названиями — тогда
  плагин возьмет значения из заказа и ничего спрашивать не будет. Псевдонимы позволяют
  принимать `uid`, `ид персонажа` и т.п.
- **Источники (variant).** В legacy API одна и та же игра может быть в двух источниках
  (1 и 2) с разными ценами — источник указывается 4-м полем привязки. В v2 не используется.
- **Ошибки.** `-200` игра не найдена (неверный ID в привязке), `-201` позиция не найдена
  (номинал снят с продажи — проверьте каталог), `-2` недостаточно средств. Деньги при
  `failed`/`cancelled` возвращаются на баланс DesslyHub.
- **API-ключ** хранится только на вашем сервере в `settings.json`, в меню показывается
  маскированным, в логи не пишется и никуда не передается, кроме `desslyhub.com`.

## Используемые методы API DesslyHub

| Поколение | Метод | Зачем |
|---|---|---|
| v2 | `GET /api/v1/catalog/mobile-refill/games` | каталог игр (поиск в меню) |
| v2 | `GET /api/v1/catalog/mobile-refill/games/{id}` | номиналы, цены, обязательные поля |
| v2 | `POST /api/v1/orders` (`service_type: mobile_refill`) | покупка (`reference` = номер заказа) |
| v2 | `GET /api/v1/orders/{order_id}` | опрос статуса до `success`/`failed`/`cancelled` |
| v2 | `GET /api/v1/balance` | баланс мерчанта |
| v2 | `GET /api/v1/currency/exchange_rates/steam/{code}` | курс для маржи |
| legacy | `GET /service/mobile/variant/{v}/games` | каталог игр источника v (1/2) |
| legacy | `GET /service/mobile/variant/{v}/games/{id}` | номиналы и поля |
| legacy | `POST /service/mobile/variant/{v}/games/refill` | покупка пополнения |
| legacy | `GET /merchants/transaction/{id}/status` | опрос статуса |
| legacy | `GET /merchants/balance` | баланс мерчанта |
| legacy | `GET /exchange_rate/steam/{code}` | курс для маржи |

Документация: [desslyhub.readme.io](https://desslyhub.readme.io/reference/introduction),
коды ошибок: [error-codes](https://desslyhub.readme.io/reference/error-codes).

  привязки и псевдонимы полей, извлечение полей из заказа и чата, полный цикл в DRY-RUN и

  идемпотентность, восстановление после перезапуска, поллер и таймауты, удаление плагина).
  Запуск из корня FunPayCardinal:
  ```bash
  cp tests_plugin_mobile_topup.py /path/to/FunPayCardinal/
  cd /path/to/FunPayCardinal && pip install -r requirements.txt && python3 tests_plugin_mobile_topup.py
  ```
  Тесты создают настройки во временной папке — ваши реальные `storage/plugins/mobile_topup/`
  не затрагиваются, запросов в интернет нет.
